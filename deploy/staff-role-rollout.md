# 관리자·수거 담당자 분리 운영

관리자는 `/admin`에서 신고·통계·처리 이력을 확인하고 최종 반려를 결정합니다. 수거 담당자는 별도 `/collect` 화면에서 소속 기관의 수거 대상을 확인하고 현장 처리합니다. 두 사람은 기존 `admins` 테이블에 각각 `TENANT_ADMIN`, `COLLECTOR` 역할로 등록하며 로그인 양식과 인증 세션을 공유합니다. 플랫폼 운영 계정 `PLATFORM_ADMIN`은 별도입니다.

| 작업 | 기관 관리자 | 수거 담당자 |
| --- | --- | --- |
| 관리자 대시보드·통계·신고 관리 | 허용 | 거부 |
| 신고자 연락처·관리자 내부 메모 | 허용 | API 응답에서 제외 |
| 소속 기관의 미완료 신고 위치·현장 사진·길찾기·QR 재확인 | 관리 화면에서 확인 | 허용 |
| 현장 수거 완료 | 관리 화면에서 처리 | 허용 |
| 현장에 기기가 없다는 사실 기록 | 최종 판단 | 사유를 기록하되 신고 상태는 유지 |
| 신고 최종 반려 | 허용 | 거부 |

관리자 로그인 후 `/admin/dashboard`, 수거 담당자 로그인 후 `/collect`로 이동합니다. 메뉴 표시와 별개로 서버가 매 요청의 역할 및 기관을 검사합니다. 수거 담당자가 관리자 URL이나 `/api/admin/dashboard`, `/api/admin/reports` 등에 직접 접근해도 403이 반환되어야 합니다. 관리자도 수거 전용 API를 사용할 수 없습니다.

## 계정 발급

운영 적용 기록(2026-11-03): `collector1@parkick.com`은 `local-development` 기관의 `COLLECTOR` 계정으로 이미 발급했습니다. 기존 `PLATFORM_ADMIN` 계정은 유지했습니다. **같은 운영 서버에서 아래 발급 명령을 다시 실행하지 마세요.** 아래 절차는 새 환경에 계정을 처음 발급할 때 참고합니다.

기존 관리자 계정이 있다면 **관리자 정보를 다시 입력하거나 만들 필요가 없습니다.** 수거 담당자 한 명만 추가합니다.

1. 새 역할과 현장 미발견 기록용 DB 마이그레이션을 적용하고 서버 코드를 배포합니다. 배포 전에는 아래 명령을 실행하지 않습니다.
2. 운영 EC2에 SSH로 접속합니다. 시연 기관 코드가 `local-development`이고 `tenants` 테이블에 활성 상태로 등록되어 있는지 확인합니다. 이 코드는 실제 지자체 관할을 의미하지 않습니다.
3. 발급할 수거 담당자 이메일은 `collector1@parkick.com`, 표시 이름은 `수거 담당자 1`입니다. 운영 EC2의 터미널에서 실행합니다.

```bash
cd /srv/parkick/app
sudo -u parkick node --env-file=/etc/parkick/backend.env --import tsx deploy/create-collector-account.ts --tenant-code local-development --email collector1@parkick.com --name '수거 담당자 1'
```

성공하면 터미널에 **이메일과 임시 비밀번호가 한 번 표시**됩니다. 이 비밀번호를 수거 담당자에게 별도로 전달하고, `https://15.165.235.154/admin/login`에서 로그인해 `/collect`로 이동하는지 확인합니다. 비밀번호는 명령 인자, `.env`, 문서, Git에 입력하지 않습니다. 기존 관리자 계정과 비밀번호는 변경되지 않습니다.

명령은 운영 `NODE_ENV=production`, 로컬 PostgreSQL `127.0.0.1:5432/parkick`의 `parkick_app` 계정, **실제 터미널**을 요구합니다. 이메일은 소문자로 저장되며 기존 이메일이 대소문자만 달라도 중복으로 거부합니다. 실패하거나 비밀번호를 놓친 경우 임의로 같은 이메일로 다시 실행하지 말고 계정 상태를 확인하세요. 별도의 비밀번호 재설정 절차가 필요합니다.

기존 `deploy/create-staff-accounts.ts`는 처음부터 관리자와 수거 담당자 **둘 다 없는** 환경을 위한 대량 발급 스크립트입니다. 이미 관리자 계정이 있는 현재 운영 환경에서는 위의 단독 발급 명령을 사용합니다.

## 시연·검증

1. 관리자 계정으로 로그인해 신고 상세와 통계를 확인합니다.
2. 로그아웃한 뒤 수거 담당자 계정으로 로그인합니다. 가까운 신고 목록·지도·길찾기·사진·QR 확인을 사용합니다.
3. 기기가 있으면 수거 완료를 기록합니다. 기기가 없다면 사유를 현장 미발견 기록으로 남깁니다. 이 단계만으로 신고는 반려되지 않습니다.
4. 관리자 계정으로 다시 로그인해 수거 이력 또는 미발견 기록을 확인하고, 필요하면 공개 사유를 적어 최종 반려합니다.
5. 수거 계정으로 관리자 화면과 API를 직접 요청해 403을 확인합니다. 다른 기관 신고의 목록·상세·사진 URL도 읽을 수 없어야 합니다. 수거 API 응답에 연락처와 내부 메모가 포함되지 않는지도 확인합니다.

서로 다른 브라우저 프로필에서 각 계정으로 시연하면 세션이 섞이지 않습니다. 운영 데이터의 상태를 바꾸는 시연은 별도 시험 신고로만 진행합니다.
