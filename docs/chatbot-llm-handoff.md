# 챗봇 기술 안내

이 문서는 팀원의 `v6-gateway` 전달본을 현재 파킥 소스에 맞춰 병합한 결과를 설명합니다. 원본 `APPLY.md`의 `LLM_*` 챗봇 환경변수는 현재 사진 판별 경로와 충돌하므로 `CHATBOT_*`로 바꾸었습니다. 적용 방법은 [빠른 안내](chatbot-quickstart.md)를 참고하세요.

## 동작과 API

공개 페이지의 플로팅 챗봇에서 추천 질문과 일치하는 질문은 `shared/chatbot-faq.json`으로 즉시 답합니다. 자유 질문은 `POST /api/chat`에 `{ "question": "...", "history": [] }`를 보냅니다. 질문은 1~300자, 문맥은 최근 완료된 user/assistant 최대 3쌍·총 3,600자입니다. 성공 응답은 `{ "data": { "mode": "gateway", "answer": "..." } }`입니다. `mode`는 `faq`, `mock`, `gateway` 중 하나입니다. 홈 FAQ는 별도 `frontend/src/features/home/homeFaq.ts`를 사용하며 홈 카드 3개는 관련 챗봇 답변을 엽니다.

서버의 `GatewayChatProvider`는 `CHATBOT_BASE_URL` 뒤에 `/v1/chat/completions`를 붙여 Bearer 인증으로 요청합니다. 고정 시스템 프롬프트, 최근 문맥, 현재 질문을 분리된 메시지로 보냅니다. 스트리밍·자동 재시도·도구 호출은 사용하지 않습니다. 응답은 정상 종료된 assistant 텍스트만 수락하고 길이·크기를 제한합니다. 공급자 오류 본문과 키는 브라우저로 전달하지 않습니다. 대화는 브라우저 메모리에만 유지되며 초기화나 새로고침 시 사라집니다.

`/api/chat`은 공개 경로이지만 허용된 브라우저 Origin과 JSON 요청만 받습니다. 기존 16KB JSON 본문 제한을 적용하고, 1분당 IP별 10회·전체 60회로 제한합니다. 모델 비용과 호출량은 게이트웨이에서도 별도 한도를 설정하는 편이 좋습니다. 질문과 문맥에서 흔한 전화번호·이메일·키 패턴을 거부하고 개인 신고 조회·처리 요청에는 고정 안내를 반환합니다. 이 필터가 모든 개인정보나 모든 언어의 명령을 완벽히 잡는 것은 아닙니다. 화면에도 개인정보를 입력하지 말라고 안내합니다. 모델 답변은 React 텍스트로 출력하며 HTML로 실행하지 않습니다.

## 현재 신고 서비스에 맞춘 지식

신고 화면은 업체·기기번호 확인 → 현장 사진 → 위치 확인 → 신고 유형 → 연락처(선택)의 **5단계**입니다. 업체와 기기번호는 필수이며 QR이 읽히지 않으면 직접 입력합니다. 사진은 1~2장, 원본 장당 10MiB 이하입니다. 운영의 LiteLLM 사진 판별은 정제된 사진을 외부 이미지 모델로 보내고, 무관한 사진이 있거나 모두 불확실하면 다음 단계와 접수를 막습니다. 촬영 중 AI 안내는 구도 조언이며 최종 사진 검사를 대신하지 않습니다. 전화번호를 남긴 신고는 인증번호 없이 번호로 상태를 조회할 수 있습니다. 관리자 화면에서는 접수·반려·수거 완료를 사용하고, 과거 처리중·견인 기록은 조회될 수 있습니다. 챗봇은 특정 신고에 접근하거나 신고를 실제 지자체에 전달하지 않습니다.

서비스 지식은 `shared/chatbot-service.json`과 `shared/chatbot-faq.json`에 보관하며 서버 시작 시 읽습니다. 배포 패키지에는 두 파일을 원래 상대 경로에 포함하고, 내용을 바꾼 뒤에는 백엔드를 재시작해야 합니다. 홈 FAQ는 프런트엔드 빌드에 포함됩니다. 기존 사진 판별·S3·DB 환경변수와 `/api/ai/*` 유산 API는 챗봇이 바꾸지 않습니다.

## 검증 범위

백엔드 테스트는 요청 검증, Origin, 속도 제한, 게이트웨이 HTTP 형식, 오류 정제, 시간 초과·취소, 개인정보/행동 경계를 네트워크 호출 없이 검사합니다. 브라우저 테스트는 FAQ, 자유 질문, 최근 문맥, 재시도·초기화, 홈 카드 연결, 모바일·키보드 화면을 확인합니다. Mock 테스트 결과만으로 실제 게이트웨이 호출이나 모델의 답변 품질을 증명할 수 없습니다. 운영 EC2 배포 후 실제 HTTPS `POST /api/chat`이 `mode=gateway`와 답변을 반환하는지 확인했습니다.
